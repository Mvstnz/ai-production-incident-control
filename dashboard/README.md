# Operations dashboard

English React 19.2.8 / TypeScript / Vite 8.2.2 interface for the actual Operations API. Synthetic data, simulated AI, sandbox mode, demo clock and role remain visible. No KPI fixtures, frontend risk calculations or invented workflow progress are included.

## Start

From the repository root, after backend bootstrap and n8n deployment:

```powershell
rtk npm ci --ignore-scripts
rtk npm run dev
```

Development URL: `http://127.0.0.1:5173`. Vite proxies only `/api` to the loopback Operations API on port 8000. Stop the Compose dashboard before using the same development port.

Container build and start:

```powershell
rtk docker compose build dashboard
rtk docker compose up -d dashboard
```

The production image uses Node 24.12.0 to build and nginx 1.28.0-alpine to serve static files on container port 80. Compose publishes only loopback port 5173. `/api` forwards to `ops-api:8000`; nginx re-resolves the service through Docker DNS so backend container replacement does not leave a stale upstream address. `/internal` and `/erp` return 404. CSP, frame denial and MIME-sniffing protection are enabled. Assets, fonts and icons require no external requests.

Sign in using an account generated by bootstrap in ignored `.local/credentials.json`. Passwords and service tokens are never bundled. Sessions use the backend's HttpOnly cookie; the returned CSRF token stays in memory. Reload obtains a new CSRF token from `/api/auth/me`.

## Views

- `#/overview`: actual scope KPIs, type/severity/status/Berlin-time filters, 25-row pagination, explicitly page-local text search. KPIs describe the whole selected scope; register filters do not silently redefine them.
- `#/incidents/{id}`: source evidence, immutable revisions, original vs. revised allocation, unconfirmed split what-if, risk factors and policy version, exact plans, action receipts and audit trail. A confirmed-split demo submits a new intake. A Quality manager can propose a separate release after a successful block; a fresh approval is required.
- `#/approvals`: pending/history requests, exact required role and expiry, payload and hash review, rationale, Approve/Reject/Modify. Modify sends the complete revised plan for backend validation and a new immutable version. Admin is the application superuser and may act for every business role; the recorded actor remains the admin account.
- `#/reliability`: job/execution references, errors/DLQ, controlled administrator retry, registered waits, outbox, sandbox notifications and provider outcomes. Unknown outcomes are shown explicitly without a blind-retry control.

The three guided starts create a new scope through `/api/demo/runs`. The source-event tracker polls persisted source and job states and links the correlated incident. Viewers inspect existing shared scopes but cannot start or revise demos or submit decisions.

## Browser verification checklist

Use actual local API/n8n records; do not mock routes or inject fictional KPI responses.

1. Sign in, reload the page, inspect scope data and start each guided scenario as an operational role. Record source/job/workflow/execution identifiers.
2. Verify the supplier baseline and hypothetical split against the API, then submit a confirmed-split revision and observe changed values and superseded approvals.
3. Inspect evidence, risk policy, original/revised completion dates, exact action payloads and audit records.
4. As the exact responsible role, review the approval dialog, rationale and confirmation. Verify Approve, Reject, Modify and stale-version 409 behavior against stored records.
5. Verify a viewer has no approval/demo mutation controls, and that server role/CSRF/scope enforcement still rejects unauthorized requests.
6. Inspect real recovery, wait, DLQ and unknown-outcome records. Test a permitted controlled retry only for a real retryable error.
7. Check keyboard navigation, native dialog focus/Escape behavior, visible focus, horizontal table scrolling and mobile navigation at narrow width.

Source formatting uses pinned Prettier 3.9.6. Reformat only frontend files with `rtk npm exec -- prettier --write dashboard/src`.
